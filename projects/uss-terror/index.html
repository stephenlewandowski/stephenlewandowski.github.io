Project development brief

USS Terror map

A transparent record of an early-stage map-based project: what is known, what remains open, and what must be established before an interactive map is presented.

Status: early project definition

01 · Current record

What is documented.

The current website and project request establish the project title, its map-based form, and that it remains in development. No reviewed source presently establishes a public purpose statement, target audience, geographic scope, dataset, historical source inventory, or technical implementation.

This page therefore treats those items as open decisions rather than presenting plausible details as facts.

02 · Purpose & audience

Questions before design.

  • What question should the map help a visitor answer?
  • Is the primary audience scholarly, educational, public-history, exploratory, or personal?
  • What geographic and temporal boundaries belong in the first release?
  • What level of uncertainty and source disagreement must the interface display?

03 · Sources

Inventory before interpretation.

No source inventory has yet been approved for publication. The next source step is to create a record for each candidate source that captures citation, date, type, geographic coverage, relevant claim or feature, reuse rights, uncertainty, and the exact map element it may support.

Historical narrative, geospatial data, reconstructed coordinates, and interpretive hypotheses should remain visibly distinct.

04 · Methods

Method follows the question.

No mapping stack or analytical method has been selected. The technical decision should follow the approved audience, source formats, uncertainty needs, and desired interaction. A lightweight static map may be sufficient for a bounded narrative; a documented data pipeline and interactive interface would be justified only if the research question requires them.

05 · Next development gate

A five-part foundation.

  1. Write the project question. One sentence identifying the decision, interpretation, or exploration the map supports.
  2. Name the audience and scope. Define geography, time period, reading level, and intended use.
  3. Build the source inventory. Record provenance, rights, confidence, and map relevance.
  4. Choose the minimum viable map. Select a method only after reviewing the sources and uncertainty.
  5. Prototype and document. Test legibility, accessibility, mobile use, citations, and the distinction between fact and reconstruction.

Information needed for the next version

Research notes, candidate sources, sketches, map files, geographic scope, preferred audience, and any existing code or repository. These remain tracked in the site's content checklist.
